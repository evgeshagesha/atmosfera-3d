## 2. Где находится текущий сайт на сервере

| Путь | Назначение |
|------|------------|
| `/var/www/egoshev.ru` | Проект **Next.js** (~783 МБ с `node_modules`) |
| `/etc/nginx/sites-available/egoshev.ru` | Прокси: порт 80 → `127.0.0.1:3000` |
| `server_name` | `egoshev.ru` `www.egoshev.ru` **и IP** `5.42.96.101` (`default_server`) |

Есть файл `.env.production.local` — **не читали и не копируем в git**.

**Важно про DNS:**

| Имя | Куда смотрит (на момент аудита) |
|-----|----------------------------------|
| `eg.egoshev.ru` | `5.42.96.101` (этот сервер) |
| `egoshev.ru` (основной) | см. REG.RU — у людей в интернете обычно **Tilda**; на VPS лежит черновик Next |

Пока основной домен указывает не на этот IP — продакшен Tilda **не ломается** правками только на VPS.  
Но конфиг Nginx на VPS **называется** `egoshev.ru` — при переключении DNS это станет критично. Тестовый WordPress делаем **отдельно**: `eg.egoshev.ru`.

## 5. Можно ли безопасно разместить WordPress + автоматизации?

**Да**, при условиях:

1. Отдельный vhost: только `eg.egoshev.ru`  
2. Отдельная директория: `/var/www/eg.egoshev.ru` (не внутри Next)  
3. Отдельная БД MySQL/MariaDB + отдельный пользователь  
4. SSL через Certbot после проверки DNS  
5. Staging: `noindex` + Basic Auth + `X-Robots-Tag`  
6. Бот/webhook — позже, лёгкий стек (Python), без тяжёлых локальных AI-моделей  

Next.js на `:3000` и WP на `eg.` могут жить рядом: Nginx разводит по `server_name`.
