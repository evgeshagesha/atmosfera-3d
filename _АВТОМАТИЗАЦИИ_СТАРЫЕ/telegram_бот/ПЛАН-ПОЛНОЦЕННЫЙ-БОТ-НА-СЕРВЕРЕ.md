## Этап 1. Посадить бота на сервер (24/7)

Цель: бот [@IcEG_bot](https://t.me/IcEG_bot) работает круглосуточно на твоём сервере Beget, не зависит от включённого Mac.

### Шаг 1.1. Подготовка на компьютере

- Убедись, что в папке `eg-community-bot` есть всё: `bot.py`, `config.py`, `requirements.txt`, папки `knowledge_base`, `deploy`, файлы `courses_links.json`, `user_state.py`, `webhook_prodamus.py` и т.д.
- На сервер **не** загружай папку `venv` и файл `.env` (их создашь на сервере).

### Шаг 1.2. Подключение к серверу

- **Если готов пользоваться Терминалом на Mac:**  
  Открой Терминал → `ssh твой_логин@IP_сервера` (например `ssh egoshev@45.152.87.216`), введи пароль.
- **Если без Терминала:**  
  Зайди в панель Beget → Файловый менеджер и Консоль (или SSH). Файлы залей через менеджер или через FileZilla по SFTP. Подробно: **ПОСАДИТЬ-БОТА-НА-СЕРВЕР-BEGET-БЕЗ-ТЕРМИНАЛА.md**.

### Шаг 1.3. Залить файлы бота на сервер

- Создай на сервере папку, например: `~/eg-community-bot` (или `/home/твой_логин/eg-community-bot`).
- Скопируй туда все файлы проекта (scp/rsync с Mac или загрузка через панель/FileZilla). Без `venv` и без `.env`.

### Шаг 1.4. Установка окружения на сервере

В консоли на сервере (или по SSH с Mac):

```bash
cd ~/eg-community-bot
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

### Шаг 1.5. Файл .env на сервере

Создай на сервере файл `.env` в папке `eg-community-bot` и заполни:

```env
TELEGRAM_BOT_TOKEN=токен_от_BotFather_для_IcEG_bot
OPENAI_API_KEY=твой_ключ_OpenAI
CHANNEL_ID=@EvgeniiGoshev
COMMUNITY_CHAT_ID=-100xxxxxxxxxx
SITE_URL=https://course.egoshev.ru
ONLINE_CLUB_URL=https://egoshev.ru
```

`COMMUNITY_CHAT_ID` — ID твоей группы (узнать: добавить бота в группу, написать в группе, открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найти `"chat":{"id": -100...}`).

### Шаг 1.6. Запуск бота как сервиса (24/7)

На сервере выполни:

```bash
cd ~/eg-community-bot
bash deploy/setup-24-7.sh
```

Скрипт создаст systemd-сервис и добавит задания в cron. Если скрипт не запускается — создай сервис вручную (инструкция в **ИНСТРУКЦИЯ-ДОБАВИТЬ-БОТА-НА-СЕРВЕР.md**).

### Шаг 1.7. Проверка

- В Telegram написать боту в личку: `/start` — должен ответить.
- Добавить бота в канал @EvgeniiGoshev как администратора с правом «Публикация сообщений».
- Добавить бота в группу сообщества и при необходимости указать в боте только эту группу через `COMMUNITY_CHAT_ID`.

После этого бот уже работает 24/7 на сервере.

## Этап 2. Приём оплаты за курс (базовая настройка тела)

Курс «Базовая настройка тела» (или отдельные модули) продаётся через Prodamus. Бот выдаёт ссылку на оплату и после оплаты — инвайт в группу.

### Шаг 2.1. Prodamus

- Создай товар/курс в Prodamus и получи ссылку на оплату.
- В `courses_links.json` в нужном курсе (например `bundle` или отдельный ключ) укажи `prodamus_url` и `telegram_invite_url` (инвайт в закрытую группу).

### Шаг 2.2. Вебхук Prodamus на сервер

- На сервере запусти приём вебхука (Flask):  
  `cd ~/eg-community-bot && ./venv/bin/python -m flask --app webhook_prodamus run --host 0.0.0.0 --port 8765` или через gunicorn/systemd (см. README).
- В Prodamus в настройках уведомлений укажи URL: `https://твой_домен_или_IP:8765/webhook` (или тот, который даёт твой сервер).
- После оплаты Prodamus шлёт запрос на этот URL, скрипт пишет заказ в `orders.json`, и пользователь может написать боту `/access НОМЕР_ЗАКАЗА` и получить инвайт.

Подробная схема: в папке сайта см. **ИНТЕГРАЦИЯ-PRODAMUS-И-БОТ.md** (или аналог на рабочем столе).

## Этап 3. Посты в Telegram-канал

- **По расписанию:** уже настроено скриптом `setup-24-7.sh`: каждый день в 10:00 запускается `generate_channel_post.py --post` — генерируется пост и отправляется в канал @EvgeniiGoshev.
- **По твоей команде «все выложи»:** сейчас такой команды нет. Можно добавить: по фразе в личку боту (например «все выложи» или «выложи пост») бот запускает генерацию и отправку поста в канал (через вызов того же скрипта или его логики). Это дорабатывается в `bot.py` при следующей итерации.

Тексты постов генерируются в стиле, который ты задал (EVOLUTION GO, анатомия, здоровье, мифы, западные исследования); база книг и стиль описаны в `knowledge_base/`.

- **Приветствие новых:** уже есть — при входе участника в группу бот пишет приветствие (текст и тон задаются в knowledge_base, файл про приветствие).
- **Ответы на вопросы как тренер/биомеханик:** бот уже отвечает на каждое сообщение в чате, опираясь на `knowledge_base/` и OpenAI. Чтобы он «всё знал про анатомию» и вёл себя как специалист по движению — нужно пополнять базу знаний (см. этап 6).

Вопросы можно кастомизировать: добавить в проект файл с твоими формулировками (например `daily_checkin_questions.txt` или блок в knowledge_base) и изменить `run_daily_group_checkin.py`, чтобы он подставлял их или выбирал случайный вопрос из списка.

## Этап 5. Память: сохранение ответов и использование в общении и программах

Сейчас ответы участников на опрос самочувствия и их сообщения в чате **не сохраняются в долгую память**: бот помнит только последние N сообщений в оперативной памяти для команды `/analiz`, после перезапуска всё обнуляется.

Чтобы:
- сохранять ответы на ежедневные вопросы (самочувствие, что делали вчера);
- использовать это при общении с людьми;
- помогать тебе составлять программы и анализировать упражнения/выполненное;

нужно добавить:

1. **Сохранение в файл (или БД):** при ответе участника в группе после опроса — сохранять user_id, дату, текст ответа (и при желании размечать, что это «ответ на опрос»).
2. **Подмешивание в контекст бота:** при ответе этому пользователю (или при запросе «составь программу для этого чата») подгружать из памяти его прошлые ответы про самочувствие и тренировки и передавать в OpenAI.
3. **Анализ и программы:** команда или сценарий вида «проанализируй ответы участников за неделю» / «предложи программу на сегодня для группы» — скрипт или бот читает сохранённую память и генерирует вывод/рекомендации.

Это следующий шаг после того, как бот стабильно работает на сервере; можно делать по шагам через Cursor (см. этап 6).

## Этап 6. Обучать бота дальше через Cursor

Чтобы бот лучше отвечал как тренер по движению, биомеханик и «знал анатомию», и чтобы появились память и команда «все выложи»:

1. **База знаний (`knowledge_base/`):**  
   Добавляй и правишь файлы `.md` / `.txt`: темы сообщества, формат приветствий и заданий, FAQ, анатомия, биомеханика, этапы EVOLUTION GO, типичные вопросы и ответы. Бот при каждом ответе подгружает эти файлы и отдаёт их в OpenAI — без перезапуска кода (достаточно перезапустить бота на сервере после правок, если нужно подхватить новые файлы).

2. **Список книг и стиль постов:**  
   Уже есть `09-baza-knig-ft.md` и стиль в `08-filosofiya-i-stil-kanala.md`. Дополняй книги и формулировки — генератор постов и ответов будет опираться на них.

3. **Новые команды и сценарии в Cursor:**  
   - Команда «все выложи»: в чате с ботом обрабатывать фразу и вызывать отправку поста в канал.  
   - Память: пошагово добавить сохранение ответов на опросы и подмешивание в контекст; потом — анализ и предложения программ.  
   Формулируй задачу («сделай так, чтобы бот по команде "все выложи" постил в канал» или «сохраняй ответы на опрос самочувствия в файл и используй при ответе этому пользователю»), и в Cursor правь `bot.py`, добавляй скрипты или новые файлы.

4. **Вопросы для ежедневного опроса:**  
   Создай файл, например `knowledge_base/daily_checkin_questions.txt` или раздел в существующем файле — список вопросов по одному на строку. Скажи в Cursor: «сделай так, чтобы run_daily_group_checkin брал случайный вопрос из этого файла» (или по расписанию по дням недели) — и тебя проведут по правкам.

5. **Сервер:**  
   После любых изменений в коде или в `knowledge_base` залей обновлённые файлы на сервер (повторно scp/rsync или через панель/FileZilla) и перезапусти сервис:  
   `sudo systemctl restart eg-community-bot`.
