# PLAUD + Notion: что построить по факту

Единый клиентский контур: захват аудио → транскрипция → распределение по клиентам/сессиям/курсам → синхронизация с Notion и Google Drive.

---

## 1. Сводка: что нужно построить

| Компонент | Назначение |
|-----------|------------|
| **Источник аудио** | PLAUD (или любой диктофон) — запись консультаций, тренировок, уроков, follow-up. |
| **Точка входа** | Локальная папка на Mac: сюда вечером скидываешь файлы (или PLAUD экспортирует сюда). |
| **Локальный пайплайн** | Скрипт: сканирует папку → транскрибирует (Whisper/faster-whisper) → по имени/метаданным определяет клиента, дату, тип → создаёт транскрипт, summary, запись сессии/урока. |
| **Локальное хранилище** | SQLite (или JSON/MD по папкам): клиенты, сессии, курсы — чтобы работать без интернета. |
| **Синхронизация** | При наличии интернета: выгрузка в Notion (API) и загрузка файлов в Google Drive (API). |
| **База знаний EG** | Локально в репозитории (папка `knowledge_base/` или `knowledge_templates/`): протоколы, философия, правила — для AI-анализа транскриптов и рекомендаций. |

**Итог:** не «папки», а единый контур: запись → транскрипт → структура (клиент/сессия/курс) → витрина в Notion + файлы в Drive.

---

## 2. Два сценария захвата аудио

### Сценарий A: PLAUD как основной диктофон

- Ты записываешь в PLAUD: консультация, тренировка, урок курса, follow-up.
- **Экспорт:** вручную (скачивание транскрипта/аудио из приложения PLAUD) или через автоматизацию, если PLAUD даёт вебхук/экспорт в папку.
- **Реальность:** официальный PLAUD Dev API ориентирован на интеграторов устройств; OAuth для личных аккаунтов — в ранней бете. На практике чаще всего: экспорт из приложения в файл → ты кладёшь файл в папку на Mac.
- **Рекомендация:** настроить в PLAUD экспорт (если есть) в одну папку; иначе — ручное копирование в `inbox_audio/` с соблюдением конвенции имён (см. ниже).

### Сценарий B: Локальная папка на Mac (универсальный)

- В течение дня записываешь на любой диктофон (в т.ч. PLAUD).
- Вечером копируешь файлы в папку **Inbox_Audio** (или подключаешь PLAUD и копируешь экспорт туда же).
- Локальный скрипт (запуск вручную или по расписанию):
  1. Находит все новые аудио в Inbox_Audio.
  2. Транскрибирует локально (Whisper / faster-whisper) — без облака.
  3. По имени файла (и опционально по первым фразам текста) определяет: клиент/курс, имя, дата, тип.
  4. Создаёт запись сессии или урока, summary, привязывает к клиенту.
  5. Переносит обработанные файлы в Processed, раскладывает по папкам клиентов/курсов.
  6. При наличии интернета — синхронизирует с Notion и Google Drive.

Сценарий B не зависит от того, откуда именно пришло аудио (PLAUD, другой диктофон, телефон). Главное — единая точка входа: одна папка.

## 3. Конвенция имён файлов (критично для автоматического распределения)

Чтобы скрипт стабильно раскладывал записи **без сильного ИИ**, нужен единый формат.

### Записи по клиентам (сессии)

```
client_<ИмяИлиФамилия>_<YYYY-MM-DD>_<тип>.<расширение>
```

**Типы:** `consultation` | `diagnostics` | `training` | `recovery` | `control` | `followup`

**Примеры:**
- `client_vasya_2026-03-07_consultation.m4a`
- `client_maria_2026-03-08_training.mp3`
- `client_andrey_2026-03-09_followup.m4a`

Если в системе уже есть справочник клиентов (по имени/фамилии), скрипт по токену `client_vasya` находит карточку «Василий» и привязывает сессию к ней.

### Записи по обучению / курсам

```
course_<короткое_название>_<модуль>_<урок>.<расширение>
```

**Примеры:**
- `course_fp_week6_lesson2.m4a`
- `course_breathing_module1_lesson3.mp3`

Короткое название (fp, breathing) можно маппить на «Название курса» в базе «Обучение/курсы» в Notion.

### Голосовая подсказка в начале записи (альтернатива/дополнение)

Если не хочешь переименовывать файлы, в начале записи можно говорить:
- *«Клиент Василий, первичная консультация, 7 марта»*
- *«Курс FP, неделя 6, урок 2»*

Тогда после транскрипции можно (вариант с небольшим ИИ) парсить первые 1–2 предложения и заполнять тип/клиента/дату. Это менее стабильно, чем строгое имя файла, но удобнее в полевых условиях.

## 4. Структура папок на Mac (в eg-ecosystem или рядом)

```
eg-ecosystem/
├── inbox_audio/              # Сюда кидаешь все новые записи (единая точка входа)
│   └── .gitkeep
├── processed/                # Обработанные аудио (перенесённые после транскрипции)
│   ├── clients/
│   │   └── <client_slug>/    # По одному на клиента (vasya, maria)
│   │       └── 2026-03-07_consultation.m4a
│   └── courses/
│       └── <course_slug>/
│           └── week6_lesson2.m4a
├── data/
│   ├── db/                   # SQLite: clients, sessions, assessments, courses
│   │   └── eg_local.db
│   ├── transcripts/          # Текстовые транскрипты по сессиям/урокам
│   │   ├── clients/
│   │   └── courses/
│   ├── summaries/            # Summary и выводы по сессиям (JSON/MD)
│   └── exports/              # Временные экспорты для Notion/Drive
├── knowledge_base/           # База знаний EG для AI-анализа (протоколы, философия)
│   └── (ссылка или копия knowledge_templates + протоколы)
├── scripts/                  # Локальные скрипты пайплайна
│   ├── transcribe.py         # Транскрипция (Whisper/faster-whisper)
│   ├── process_inbox.py      # Сканирование inbox → транскрипт → распределение
│   ├── sync_notion.py        # Выгрузка в Notion API
│   └── sync_drive.py         # Загрузка файлов в Google Drive
└── .env.example              # NOTION_TOKEN, NOTION_DB_*, GOOGLE_CREDENTIALS, etc.
```

Notion и Google Drive остаются облачными; локально — только папки + SQLite + скрипты.

## 5. Что куда попадает после обработки

| Что | Локально | Notion | Google Drive |
|-----|----------|--------|--------------|
| Карточка клиента | SQLite `clients` | База «Клиенты» | — |
| Одна сессия | SQLite `sessions` + файл транскрипта | База «Сессии» (relation на клиента) | Аудио в папке клиента |
| Оценка/диагностика | SQLite `assessments` | База «Оценка/диагностика» | — |
| Урок курса | SQLite `course_lessons` + транскрипт | База «Обучение/курсы» | Аудио/видео в папке курса |
| Summary, жалобы, рекомендации | В записи сессии (JSON/MD) | Поля в «Сессии» / «Клиенты» | — |

Связи: **Сессии** → **Клиенты** (relation); **Оценка/диагностика** → **Клиент** или **Сессия**. В Notion то же самое через Relation.

## 6. Пайплайн по шагам (что делает скрипт)

1. **Сканирование**  
   Обход `inbox_audio/`, выбор файлов с расширениями `.m4a`, `.mp3`, `.opus`, `.wav` и т.п.

2. **Определение контекста по имени файла**  
   Парсинг имени: `client_*` → клиент + дата + тип; `course_*` → курс + модуль + урок. Если не подходит под шаблон — положить в «неразобранное» и не трогать или пометить для ручной разметки.

3. **Транскрипция**  
   Вызов Whisper/faster-whisper (локально). Язык: русский (и при необходимости английский). Результат: текст в UTF-8.

4. **Создание/обновление сущностей**  
   - Для `client_*`: найти или создать клиента по slug, создать запись сессии с датой, типом, транскриптом.  
   - Для `course_*`: создать/обновить запись урока с транскриптом.

5. **Summary и структурирование (опционально, с ИИ)**  
   По транскрипту: краткое summary, «что беспокоит», «что сделали», «ощущения после», «рекомендации», «follow-up». Можно делать локально (локальный LLM) или через API (OpenAI/другое) при наличии интернета. Результат пишется в поля сессии (локально и при синке — в Notion).

6. **Раскладка файлов**  
   Аудио переместить в `processed/clients/<slug>/` или `processed/courses/<slug>/`. Транскрипт и summary сохранить в `data/transcripts/` и в БД.

7. **Синхронизация (при интернете)**  
   - **Notion:** создать/обновить страницы в базах «Клиенты», «Сессии», «Оценка/диагностика», «Обучение/курсы» по данным из SQLite.  
   - **Google Drive:** создать папку клиента/курса (если нет), загрузить аудио (и при желании транскрипт в виде файла).

Так ты получаешь: **одна папка на входе** → **всё автоматически распределено по клиентам и курсам** → **витрина в Notion и файлы в Drive**.

## 7. Базы в Notion (напоминание полей)

Кратко; полная раскладка — в `NOTION_И_PLAUD_НАСТРОЙКА.md`.

- **Клиенты:** Имя, Возраст, Город, Telegram, Телефон, Запрос, Жалобы, Статус, Дата первой консультации, Ссылка на папку Drive, Relation на Сессии, План тренировок, Домашние задания, Обследования/МРТ, Заметки.
- **Сессии:** Клиент (Relation), Дата, Тип (консультация/диагностика/тренировка/восстановление/контроль/follow-up), Транскрипт, Summary, Что беспокоит, Оценка состояния, Что сделали, Реакция во время, Ощущения после, Рекомендации, Домашнее задание, Ссылка на аудио.
- **Оценка/диагностика:** Связь с клиентом/сессией, зоны (шея, грудной, поясница, таз, ТБС, колени, стопа, дыхание, осанка, походка) по шкале 0–3, Заметки.
- **Обучение/курсы:** Название курса, Модуль, Урок, Ссылка на аудио/видео, Транскрипт, Конспект, Ключевые идеи, Как встроить в EG.
- **Протоколы и рекомендации:** Библиотека EG (зоны, протоколы, упражнения) — для подстановки в рекомендации по транскриптам.

---

## 8. Где что хранить (итог)

- **Notion:** структура, связи, аналитика, витрина для тебя — клиенты, сессии, оценки, курсы, протоколы.  
- **Google Drive:** тяжёлые файлы — аудио, видео, PDF, фото, МРТ.  
- **Локально (Mac):** папка входа, транскрипция, локальная БД, скрипты; при появлении интернета — синхронизация в Notion и Drive.

Не полагаться на интернет для транскрипции: она локальная. Notion/Drive — слой синхронизации.

## 9. Роль бота (если делаешь через бота на сервере)

По твоему ТЗ и ARCHITECTURE:

- **Внешний бот (Sales/Community):** заявки, опросники, ссылки на продукты; не обязан знать карточки клиентов из Notion.
- **Внутренний бот (Internal):** для тебя: создание клиента, привязка сессии, загрузка аудио/транскрипта, получение summary и рекомендаций. Тогда сервер бота может вызывать тот же пайплайн: при получении голосового/аудио — транскрипция → разбор → запись в БД → синк в Notion.

Локальный пайплайн (папка на Mac) и бот могут сосуществовать: папка — для «вечернего сброса» файлов с PLAUD/диктофона; бот — для работы «на ходу» с телефона (голосовое в чат → сервер обрабатывает и пишет в те же Notion/БД).

## 10. Что сделать в первую очередь (порядок внедрения)

1. **Создать папки** в `eg-ecosystem/`: `inbox_audio/`, `processed/`, `data/db/`, `data/transcripts/`, `data/summaries/`, `scripts/`, при необходимости `knowledge_base/` для скриптов.
2. **Зафиксировать конвенцию имён** и один раз описать её в README или в этом файле (уже сделано выше).
3. **Настроить Notion:** базы Клиенты, Сессии, Оценка/диагностика, Обучение/курсы, Протоколы — по `NOTION_И_PLAUD_НАСТРОЙКА.md`.
4. **Реализовать минимальный скрипт:** сканирование `inbox_audio/` → парсинг имени → транскрипция (faster-whisper) → сохранение транскрипта и запись в SQLite (таблицы clients, sessions, course_lessons). Без синка пока.
5. **Добавить синк с Notion:** по токену и ID баз создавать/обновлять страницы из SQLite.
6. **Опционально:** синк с Google Drive (папки клиентов/курсов, загрузка аудио).
7. **Опционально:** шаг summary/структурирование (локальный LLM или API) и запись в поля сессии.

После этого у тебя будет: **диктофон (в т.ч. PLAUD) → одна папка → автоматическое распределение по клиентам и курсам → витрина в Notion и файлы в Drive**, с минимальной зависимостью от интернета на этапе транскрипции.
